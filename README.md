# Gantt Pipeline

Переносимый скилл для Codex: **ТЗ → декомпозиция → задачи Aspro → подтверждение PM → интерактивный HTML Gantt → Google Sheets / публикация**.

Основной режим — разработка сайтов. Для айдентики и мобильных приложений предусмотрены отдельные начальные структуры; их детализация идёт из нового ТЗ. Режимы не содержат готовых сроков или состава команды.

## Что получает проджект

- Контекстные задачи: результат, критерии приёмки, источники, зависимости, условия старта. Повторный запуск сверяет идентификаторы и останавливается при неоднозначности, чтобы не создавать дубли.
- Отдельное подтверждение фактически заведённого пула в Aspro перед финальным Гантом.
- Один HTML-файл с настройками календаря, длительностей и потоков, группировкой, масштабом, связями, перетаскиванием задач, отменой, сохранением и загрузкой сценариев.
- Критический путь с учётом текущего порядка потоков, полный и свободный резерв. Неизвестные сроки и конфликтующие даты показаны явно.
- Ссылки на задачи Aspro и кнопка **«Обновить из Aspro»** через серверное подключение.
- XLSX с визуальным таймлайном, секциями, цветными блоками и критическими отметками; CSV для простого реестра.
- Процедура публикации HTML через доступный в Codex сервис Sites.

## Установка и запуск

Нужны Codex с поддержкой локальных скиллов и Node.js 20+. Для сценария создания задач нужен подключённый Aspro. Google Drive и Sites нужны только для соответствующих этапов доставки. Runtime-пакеты npm не требуются.

Скачайте репозиторий:

```sh
git clone https://github.com/adaptive-kez/gantt-pipeline-skill.git
cd gantt-pipeline-skill
```

Скопируйте папку `skills/gantt-pipeline` в каталог скиллов вашей установки Codex (обычно `~/.codex/skills/gantt-pipeline`). Если там уже есть версия скилла, сначала сравните её и сохраните свои изменения. Перезапустите Codex или откройте новую сессию, если скилл не появился в списке.

В чате:

> Используй $gantt-pipeline. Режим — разработка сайта. Вот ТЗ и карта страниц: … Нужны задачи в Aspro, после моего подтверждения — HTML Gantt и Google-версия. Известные оценки и потоки: …

Скилл не требует заполненного шаблона ТЗ: агент извлекает задачи из контекста. Он уточняет существенные пробелы и сохраняет неизвестные значения. Командный скрипт проверяет и собирает подготовленную модель; сам по себе он не выполняет AI-декомпозицию и не создаёт записи в Aspro.

## Быстро посмотреть шаблон

Вымышленный пример полностью автономен:

```sh
node skills/gantt-pipeline/scripts/pipeline.cjs build \
  --project skills/gantt-pipeline/examples/website-project.json \
  --preview --out output/demo.html
```

Откройте `output/demo.html` в браузере. Для повторной сборки укажите новое имя, например `output/demo-v2.html`: существующие файлы не перезаписываются. У демонстрации нет реальных задач Aspro или подтверждения PM, поэтому она помечена как черновик.

## Как устроено обновление Aspro

Кнопка читает актуальные названия, сроки, этапы и статусы, добавляет новые задачи и пересчитывает сценарий. Существующие задачи сопоставляются по Aspro ID. Удалённые/архивные записи остаются с предупреждением; новая задача без оценки не получает выдуманный интервал. Локальные изменения сценария не записываются в Aspro.

В пакет включён **локальный сервер только для чтения**, который хранит API-ключ в серверной среде и отдаёт очищенную модель по `/api/aspro/snapshot`. Настройка: [sync.md](skills/gantt-pipeline/references/sync.md). Проекты, секции и шаблон ссылок каждый пользователь проверяет в своём Aspro.

У HTML-файла на диске и у статической публикации нет безопасного места для API-ключа. Без настроенного подключения кнопка неактивна. Для обновления на опубликованном сайте требуется защищённый серверный маршрут на том же домене. Локальный bridge не является публичным production-сервером. Не размещайте ключ в HTML, Git, URL или localStorage.

## Google Sheets и публикация

В HTML кнопка **«Excel сценария»** экспортирует именно текущий сценарий. XLSX содержит листы `Гант`, `Задачи`, `Сценарий`, `Календарь`. Для Google-версии импортируйте XLSX с преобразованием в Google Sheets и проверьте результат. Это оформленный **статический снимок**: автоматический пересчёт связей и чтение Aspro остаются в HTML.

Публикация через Sites выполняется агентом по запросу с проверкой фактического URL. Открытый репозиторий скилла не делает клиентские планы публичными. В репозитории нет настоящих клиентских данных или настроенного аккаунта.

## Тесты и ограничения проверки

```sh
npm test
```

Тесты используют встроенный Node test runner, синтетические проекты и подставной Aspro API. Покрыты расчёт ресурсов и критического пути, зависимости, переносы, неизвестные оценки, подтверждение состава, отсутствие дублей, исходные даты, экспорт, фильтрация закрытого контекста и HTTP-границы синхронизации.

Дополнительно при подготовке версии проверены браузерный интерфейс, два обновления источника подряд, независимый запуск скилла на неполном ТЗ и импорт синтетического XLSX в настоящую Google-таблицу с чтением дат и закреплений. Это не подтверждает доступ к Aspro другого пользователя или настройку серверного маршрута на его сайте. Подключение и публикация проверяются отдельно при запуске проекта.
